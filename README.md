# Trophy Count

A static site that counts the awards K-pop groups won from 2020 to 2026: Korean ceremonies, weekly music shows and international awards, for the 30 most-awarded groups. Every win links to its source.

- `/` leaderboard with filters (years, Korea or international, music shows on/off, boy/girl, generation, sort, search). Filters live in the URL.
- `/groups/<slug>/` one page per group: totals and ranks, wins by year, top ceremonies, most-awarded songs with an in-page player, photos, members, every awarded release with Spotify / Apple Music / YouTube Music links, and the full list of wins.
- `/compare/?g=a,b,c` two or three groups side by side.
- `/ceremonies/?c=<id>` who won each ceremony, year by year.
- `/about/` how wins are counted, sources and known gaps.

## Run it

```bash
npm install
npm run dev          # http://localhost:3000
npm run build        # validates the data, then writes the static site to out/
npm start            # serves out/ locally
```

`out/` can be uploaded to any static host (Vercel, Netlify, GitHub Pages, S3). Set `NEXT_PUBLIC_SITE_URL` at build time so share images get absolute URLs.

## Data pipeline

The data in `src/data/` is generated by scripts in `scripts/`, never typed by hand:

| Step | Command | What it does |
|---|---|---|
| Scrape | `npm run data:scrape` | Music-show wins from Wikipedia's yearly winner lists; ceremony wins from each group's Wikipedia awards list |
| Build | `npm run data:build` | Maps ceremony names to `scripts/ceremonies.config.ts`, tags daesang/bonsang, picks the top 30 from the candidate pool in `scripts/groups.config.ts`, writes `awards/` and release stubs |
| Profiles | `npm run data:groups` | Fandom-wiki profile facts plus Wikimedia Commons photos (hero, gallery, members), then thumbnails |
| Releases | `npm run data:releases` | Apple Music links, cover art and dates (iTunes Search), YouTube Music links, Spotify links (Wikidata, or the Spotify API when `SPOTIFY_CLIENT_ID` and `SPOTIFY_CLIENT_SECRET` are set) |
| Share images | `npm run data:og` | Renders `public/og/*.png` (one per group plus the home page) and the placeholder tab icon `src/app/icon.png` |
| Validate | `npm run data:validate` | Schema, date range, unknown ids, duplicates, missing sources and missing image files. Runs before every build |

`npm run data:refresh` runs all of them in order. HTTP responses are cached in `.cache/`, so re-runs are fast; delete it to fetch fresh data. Manual fixes go in `src/data/corrections.json` as `{ "remove": [...], "add": [...] }`, each with a `reason`.

Thumbnail generation and PNG-to-JPEG conversion use macOS `sips`.

## Decisions

- **Korean vs international** follows the organizer's country, not the venue (MAMA in Japan is still Korean).
- **Music shows count toward the total** but keep their own color and a filter, because they would otherwise hide how a group does at ceremonies.
- **Colors:** warm paper neutrals so photos and each group's own colors carry the page; charts use three validated categorical slots (blue Korean awards, aqua music shows, orange international) and one blue ramp for the heatmap.
- **Type:** IBM Plex Sans KR draws Hangul and Latin names with one voice; Big Shoulders gives condensed scoreboard numerals that fit next to photos on phones.
- **Group accent:** the first official fandom color when one exists, otherwise a site-picked accent that is never presented as official.
- **Photos:** only freely licensed Commons files, each credited; no photo means an initials monogram, never a borrowed picture.
- **Leaderboard as a ranked list, not cards**, because the data is a ranking and the rows need to line up.
- **Heatmap instead of a 10-series stacked chart** for year-by-year, because more than three series cannot be told apart by color.
